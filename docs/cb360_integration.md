# CB360 接入与使用

CB360 通过 GetSysInfo 的型号与协议版本识别，保留旧设备识别流程。连接后使用统一的 SetBaud 协商到 2000000 bps；连接栏显示实际速率，可切换 115200 / 921600 / 2000000。

## 测温与投屏

- 共用现有实时画面、测点、温度曲线、拍照和录像入口。
- 每帧 BP64 解压和 CRC32 校验在后台完成；对所有 120×90 像素计算温度。
- 使用固件相同的 C++ 整数测温算法生成查表，按有符号 Y16 查表得到摄氏度。Y16 已经过 NUC，不重复校正。
- 曲线缓存以热像模块 SN 和整个曲线集合 CRC 为依据；动态参数在连接、恢复投屏或刷新参数时重新获取。
- 目前推流帧不含曲线索引或动态参数。自动曲线依据参数快照中的 FPA 温度和固件滞回规则选择。设备校准、自动曲线或设置改变后，应在连接栏刷新测温参数；悬停刷新入口可查看参数获取时间。
- 软件拍照/录像保存完整 120×90 浮点温度，进入原有软件图库。
- CB360 的实时画面默认使用等离子色图。离开 CB360 时恢复进入前的渲染设置，避免把色图带给其他设备；软件拍照仍保存拍摄时的色图选择。

## 两栏图库

- **设备图库**：列出设备照片，按需下载，支持下载全部、删除选中项、缩略图和重复查看的内存缓存。文件夹按钮可打开已下载副本，支持断开后离线还原。
- **软件图库**：保存上位机拍照和录像。没有单独的 CB360 图库。
- 两处照片预览共用双边滤波开关、空间/亮度 sigma、上采样倍率和插值算法；调整即时作用于预览和导出，不改写原始温度或设备设置。静态照片不提供时序卡尔曼滤波。
- 照片 AI 超分仅保留 Thermal-PFT L1 / TV 原生 3×，默认关闭，Windows 扩展包缺失时不可用。实时投屏可在主画面启用 PFT TV 3×；处理队列只保留正在运行的一帧和最新待处理帧。AI 原生 3× RGB 直接进入普通/全屏画布，不再缩回普通画面尺寸；状态栏显示实际 AI 输出尺寸。AI 仅替换显示 RGB，温度场、测点和温标使用实时原始测量数据。模型来源和运行包准备方式见 `tools/photo_ai/MODELS.md`。
- CB360 实时画面默认使用等离子配色、关闭双边滤波；设备照片也默认关闭双边滤波，用户可手动开启。设备图库与软件图库的静态照片预览/导出默认使用固件同源的「铁热」色盘，也可在色盘下拉框切换；软件录像保留保存时的色盘。铁热沿用固件六段色点和整数插值，PNG 保留 RGB888，避免额外 RGB565 量化。其他设备实时默认值不变。
- CB360 下载保存在所选下载目录的 `raw/CB360` 下。设备上下文和曲线采用校验包装及临时文件发布。照片完整接收并验证后，以全量内容和还原参数建立缓存；同一列表内重复查看不再传输。
- 设备 ID 删除后可能重用，因此刷新列表必须重新确认完整照片，不能仅凭 SN+ID 或前 4 KB 命中磁盘缓存。旧版独立目录的下载文件仍可离线读取。

## 验证范围

- 必要数据测试：CRC、分包/粘包、BP64、会话变化、曲线更新失效、全像素温度、120×90 拍照/录像、旧设备帧与照片解析。
- 原生算法曾以 10 张已有实机照片对比：每张 10800 个温度与参考 CSV 一致，还原 BMP 一致。
- Windows 发布构建；Android 原生工程已接入，尚未进行 Android 构建或实机验收。
- 按用户要求不做 Flutter 页面测试，界面由用户验收。
- `tools/cb360_hardware_check.dart COM144` 是可选的只读实机检查：统一 RX 路径、2M 下载、全像素温度比对、20 秒推流，输出放在忽略的 build 目录，不删除设备照片。当前新增串口读取生命周期修正尚待设备复测；本轮设备端口消失后未继续占用串口。
