# 温度报警串口协议 v1

设备使用 USB CDC 串口向 BananaThermal Studio 发送报警。若专用蜂鸣器模块也通过 USB 接在电脑上，Studio 会把同一条报警事件原样、优先转发到用户选择的第二串口；模块中途接入时会先收到 H/L 两个通道的当前状态。报警事件协议刻意保持为一条固定 17 字节 ASCII 行；蜂鸣器 MCU 不需要 JSON、浮点数、校验库或二进制热帧解析能力。

若蜂鸣器模块本身具备 USB Host 能力并独占连接热成像设备，也可以直接消费设备输出的同一协议，不需要 Studio 参与。

## 报警事件

格式：

```text
!A,1,<kind>,<state>,<temperature_deci>\n
```

示例：

```text
!A,1,H,1,+0850
!A,1,H,0,+0575
!A,1,L,1,-0050
```

字段：

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `!A` | 固定 | 报警行魔数 |
| `1` | 固定 | 协议版本 |
| `kind` | `H` / `L` | 过热 / 过冷 |
| `state` | `1` / `0` | 触发（或活动心跳）/ 解除 |
| `temperature_deci` | 带符号 5 字符整数 | 实测温度，单位 0.1 °C；如 `+0850` = 85.0 °C |

蜂鸣器模块的最小处理逻辑：

1. 按 `\n` 收一行，只处理以 `!A,1,` 开头且字段数正确的行。
2. 任一 `state=1` 时开启蜂鸣器；分别记录 H/L 状态，以支持两种报警同时活动。
3. 对应类型收到 `state=0` 后清除该类型；H/L 均清除后关闭蜂鸣器。
4. 重复收到相同的 `state=1` 是活动心跳，不应反复重启蜂鸣节奏。
5. 不识别的版本、类型或字段直接忽略。

事件没有 CRC：USB CDC 已有链路校验，固定魔数、字段数量和有限取值足以拒绝普通日志。活动报警默认每 1 秒重发，专用模块中途上电或偶发丢行后也能恢复状态；用户可关闭或调整重发间隔。

Studio 的“设置 → 设备温度报警”中可选择第二个 USB 串口作为蜂鸣器模块（固定 115200、8N1）。热成像串口与蜂鸣器串口不能选择同一端口。热成像链路断开或用户主动断开蜂鸣器端口时，Studio 会先向模块发送 H/L 解除帧，避免模块因旧状态持续鸣叫。

## 配置命令

报警模块不需要实现以下命令。它们用于上位机与设备同步、修改和持久化参数。

```text
alarm get
alarm ack
alarm defaults
alarm set <master> <high_enabled> <high_c> <low_enabled> <low_c> <high_hyst_c> <low_hyst_c> <trigger_ms> <clear_ms> <latched> <repeat_ms>
```

示例：

```text
alarm set 1 1 60.0 1 0.0 2.0 2.0 500 1000 0 1000
```

约束：

- 温度范围：-40.0 ~ 300.0 °C，且过冷门槛必须低于过热门槛；
- 迟滞：0.1 ~ 20.0 °C；
- 触发/恢复确认：0 ~ 10000 ms；
- 重复上报：`0` 表示关闭，否则为 250 ~ 60000 ms；
- 布尔值只接受 `0` 或 `1`。

成功响应是一行 `type=temperature_alarm`、`version=1` 的 JSON，包含完整配置、持久化结果及当前 H/L 活动状态。失败响应使用同一类型并返回 `ok=false` 与 `error`。`alarm set`、`alarm defaults` 在响应前已经写入设备 LittleFS；上位机以回读响应为最终状态。

## 状态机语义

- 总开关默认关闭，过热和过冷分项也默认关闭；
- 过热使用每帧最高温，过冷使用每帧最低温；
- 条件持续达到 `trigger_ms` 才触发，过滤单帧尖峰；
- 过热恢复点为 `high_threshold - high_hysteresis`，过冷恢复点为 `low_threshold + low_hysteresis`；达到恢复区后还需持续 `clear_ms` 才解除；
- 锁存开启时不自动解除，必须执行 `alarm ack` 或在设备菜单选择“解除当前报警”；
- 人工确认时若温度仍未回到迟滞恢复区，该通道保持已确认/静音，不会立即重触发；先回到恢复区后才重新布防。

## 与热流/图库协议共存

报警优先级高于普通命令和推流，但不会插入一张正在发送的二进制热帧或可见光帧内部；它在下一帧开始前抢占串口，因此不会破坏 `BEGIN...END` / `VBEG...VEND` 解帧。

图库下载是逐行十六进制文本。长下载期间，报警只会在完整记录行之间插入独立 `!A` 行；图库解析器忽略该非十六进制行，报警解析器仍会立即处理。
